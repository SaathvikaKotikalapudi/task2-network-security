# TASK 2: NETWORK SECURITY AND SCANNING

## 1. Objective
The objective of this assignment is to understand network reconnaissance, port scanning, service detection, packet analysis, and firewall testing in an isolated cybersecurity lab.

## 2. Lab Environment
- Attacker/testing machine: Kali Linux
- Target machine: Metasploitable 2
- Target IP address: 192.168.56.101
- Tools used: Nmap, Wireshark, and iptables

## 3. Network Reconnaissance
Nmap host discovery was used to check whether the target machine was reachable. Connectivity was also checked using ping.

## 4. Port and Service Scanning
Nmap was used to perform TCP SYN scanning, UDP scanning, service/version detection, and operating-system detection.

The following reports were saved:
- full-scan.nmap
- tcp-scan.txt
- udp-scan.txt
- os-detection.txt

The actual open ports and detected services should be documented from these saved scan reports.

### 4.1 Actual Scan Findings

The Nmap scan identified 23 open TCP ports on the target machine, 192.168.56.101. The target responded with approximately 1.3 ms latency. Nmap reported 977 closed TCP ports in the scanned port set.

The identified services included FTP, SSH, Telnet, SMTP, DNS, HTTP, RPC, SMB, remote shell services, NFS, MySQL, PostgreSQL, VNC, IRC, AJP, and Apache Tomcat.

The operating-system detection suggested a Linux 2.6.x kernel, with an estimated kernel range of 2.6.9–2.6.33.

The following observations require attention:
- Telnet and legacy remote shell services may expose sensitive information because they lack modern secure transport protections.
- Older web, database, FTP, and DNS software may contain known vulnerabilities and should be checked against reliable vulnerability references.
- TCP port 1524 was identified as a bindshell associated with a root shell in this intentionally vulnerable lab.
- Database and file-sharing services should be restricted to authorized hosts.
- Unnecessary exposed services should be disabled or filtered.

These are initial observations from service detection, not confirmation that every service is exploitable. Further validation would be required to establish individual vulnerabilities and their severity.
## 5. Wireshark Packet Analysis
Wireshark was used to capture network traffic between Kali Linux and Metasploitable 2. ICMP traffic was observed while pinging the target.

The capture was saved as capture.pcapng.

HTTP, DNS, and FTP traffic analysis was not confirmed as completed and is therefore not reported as a verified result.

## 6. Firewall Testing
A temporary iptables rule was used to test the effect of blocking TCP port 80 on the target machine. The rule was intended to be removed after testing.

The observed connectivity result should be recorded from the actual test output. The test alone does not establish that a full port scan was blocked.

## 7. Vulnerability Scanning
Greenbone/OpenVAS setup was attempted, but a completed vulnerability scan report was not obtained. Therefore, no vulnerability severity counts or specific vulnerability findings are claimed in this report.

## 8. Security Recommendations
- Disable unnecessary network services.
- Keep operating systems and applications updated.
- Restrict access to services using firewall rules.
- Use encrypted protocols instead of transmitting credentials in plaintext.
- Perform authorized vulnerability scans and review findings.
- Save scan results and packet captures for further analysis.

## 9. Conclusion
This assignment provided practical experience with network discovery, port scanning, service identification, packet capture, and firewall testing in a lab environment. The saved reports provide evidence of the scanning activities performed. Further work is required to complete vulnerability scanning and any additional packet-analysis tasks.
